# Multica 移动端 UI 对齐需求

## 目标

参考用户提供的 Multica Go 截图，逐步把移动端主导航与关键页面补齐到同一套产品语义。所有服务器数据继续通过当前所选服务器的 API 获取；工作区功能必须受当前工作区、成员权限和接口结果约束。切换服务器后不得混用旧服务器缓存。

本需求只复用交互和信息架构，不复制对方品牌素材或逐像素照搬。移动端只呈现已经有原生页面承接的功能；未实现的功能先进入待办，不能放一个点了就空白/占位的入口冒充完成。

## 已确认的接口边界

- `GET /api/config` 是公开的部署配置，包含安全的部署级 feature flags；它不是当前用户/工作区的完整功能清单。
- `/api/workspaces`、`/api/inbox`、`/api/issues`、`/api/projects`、`/api/agents`、`/api/runtimes`、`/api/squads`、`/api/chat/*`、`/api/pins`、`/api/cloud-subscriptions/*` 等实际资源接口承载业务数据。页面需使用当前配置服务器上的 API client 与 TanStack Query。
- 资源入口是否显示，优先依据移动端是否有可用原生路由、当前账号/工作区上下文及服务端返回的数据/权限；不能仅由服务端 URL 推断能力，也不能把空数据误当作接口不支持。
- 任何新增接口需补移动端 schema/fallback、query key、取消信号和解析测试；本阶段优先复用现有 API，不新增服务端 endpoint。

## 信息架构与验收

### 1. 底部主导航

固定四项：**首页、收件箱、我的、搜索**。图标在 iOS/Android 都可见；收件箱徽标使用服务端未读汇总语义。切换服务器/工作区后仍留在相同主导航结构。

### 2. 首页

- 显示当前用户问候、当前工作区语境和新建任务/新建聊天快捷操作。
- 今日概览呈现有可靠查询支撑的摘要；数字必须注明口径，加载/失败不能伪装成 0。
- 近期动态来自当前工作区收件箱，条目可跳到对应资源并遵循已读行为。
- 验收：切工作区后标题、计数和动态同步变化；空状态、错误与加载态明确；所有卡片能到达真实页面。

### 3. 我的

按截图组织为个人资料卡、购买项目、工具、Server & Workspace、帮助/关于（仅在已有功能时）。展示当前账号、当前服务器和工作区；服务器选择仍为本地配置，不上传同步。

首期可用工具目录：聊天、任务、已固定、项目、收件箱相关设置/个人资料。只链接到真实移动端页面。智能体、自动化、Skills、运行时、团队、用量等服务端能力虽有 API，不代表移动端已有完整用户流程；需逐项完成页面后再开放入口。

购买/订阅入口仅在服务端返回适用的 Cloud 订阅摘要时呈现；自托管或不适用服务器不得显示误导性的购买项。

### 4. 搜索

- 搜索入口复用现有任务/项目搜索能力。
- 快捷入口链接聊天、任务、个人资料和已实现的原生功能。
- 最近访问按当前工作区显示，点击可回到真实详情。
- Skills 等未实现的目的地暂不放入可点击目录。

## API/页面现状清单（2026-10-15 仓库盘点）

| 功能 | 服务端 API | 移动端现状 | 计划 |
|---|---|---|---|
| 账号、服务器、工作区 | `/api/me`、`/api/workspaces` | 登录态、工作区切换、服务器配置已存在 | 整理进“我的”，服务器设置仅本地持久化 |
| 收件箱/通知 | `/api/inbox/*`、`/api/notification-preferences` | 收件箱及通知设置已存在 | 首页复用收件箱；我的页链接真实设置 |
| 任务/项目/已固定 | `/api/issues/*`、`/api/projects/*`、`/api/pins/*` | 任务、项目、已固定原生页已存在 | 作为工具入口与首页摘要 |
| 聊天 | `/api/chat/sessions/*`、`/api/chat/*` | 原生聊天页已存在 | 保留新建聊天快捷入口 |
| 智能体/运行时/团队 | `/api/agents/*`、`/api/runtimes/*`、`/api/squads/*` | 有原生只读列表；智能体可按权限开始聊天 | 后续补详情与管理闭环 |
| Skills/自动化 | `/api/skills/*`、`/api/autopilots/*` | 有 schema 校验的原生只读列表 | 后续补详情、创建与编辑流程 |
| 标签 | `/api/labels` | 有原生只读列表 | 后续补管理操作 |
| 用量/控制台 | `/api/dashboard/usage/daily` | 首页 7 日 Token 汇总及原生周用量图 | 后续补多维图表与筛选 |
| 订阅 | `/api/cloud-subscriptions/summary` | 按部署开关和操作权限显示购买项；账单动作打开当前服务器 Web 页面 | 当前 server/workspace 配置保持本地 |

## 实施顺序

1. 稳定四项主导航，修正文案与入口，不让未实现页面出现在目录。
2. 完成首页：可靠的工作区指标、近期活动、真实加载/错误/空状态。
3. 完成“我的”：个人卡片、适用的订阅信息、工具入口、当前服务器/工作区。
4. 完成搜索页：搜索入口、快捷入口、最近查看任务；验证服务器/工作区隔离。
5. 逐项补智能体、自动化、Skills、运行时、团队与用量的详情/管理流程；每项先从 API 契约和 Web/Desktop 产品行为核对，再做原生流程并开启对应操作。

每一项完成后运行移动端 typecheck/lint/test；页面改动还要在设备或模拟器检查主题、安全区、滚动、导航和真实 API 数据。不得把静态检查当作 UI 验收。

- 2026-10-15：四项底部导航、首页/我的/搜索原生页已接入当前服务器和工作区查询；智能体列表替换 coming-soon 占位，聊天按钮遵守统一调用权限；标签、Skills、自动化、运行时、团队均有工作区数据的原生只读列表；用量页使用 7 日 dashboard API；订阅入口根据部署开关和工作区权限决定是否呈现，并打开当前配置服务器的 Web 账单页。首页加载/失败不会伪装成 0。
